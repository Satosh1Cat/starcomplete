# 问题定义

开发者在补全列表里找不到**此刻最该用的那个符号**。不是「AI 写代码」。

## 一句话

默认 IntelliSense 给的是「语言服务知道的全部合法符号」，按字母或声明序排。人要的是「在这个文件、这个接收者上，团队和生态最常用的两三个」。

## 是 / 不是

**是。** 排序问题。候选已经在列表里。失败是：对的项在第 20 行，人眼扫过去选了错的，或放弃补全手打。

**不是。** 从空白生成函数。不是读仓库打补丁。不是聊天解释。那些是 Copilot / Cursor 的问题，换一套评测、延迟和权限。

## 为什么现在做

语言服务已经很好：类型、作用域、合法 API 它会列全。缺的是**先验**——`console` 后面 `log` 比 `Console` 构造器常见；`items.` 后面 `map` 比 `toLocaleString` 常见。微软 IntelliCode（2018）的判断：不替换语言服务，只重排并打星。约束比模型更重要。

## 谁痛、何时痛

写 TypeScript / JavaScript 的人，在 `.` 之后、或打了两三个字母之后。列表一长，前三个如果是 `concat` / `copyWithin` / `entries`，人会怀疑补全「不懂我」。

## 成功长什么样

打开补全，最可能的符号在最上面，带星标。人按 Enter / Tab 就走。全程本地、几十毫秒。说「更智能」之前，离线 fixtures 的 Top-1 / Top-3 必须高于原始顺序。

## 故意不解决

聊天、多文件重构、自动 commit、自己训基座。那些会把问题定义改成 agent 出荷，评测门也要从接受率换成 SWE-bench。现在不做。
