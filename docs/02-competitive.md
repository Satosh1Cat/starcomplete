# 竞品拆解

每家写四件事：用户感知、延迟、数据从哪来、他们卖的是 26 层里的哪一层。层号见 [05-layer-map.md](./05-layer-map.md) 和 NewIdea 第 2 章。

## IntelliCode（对标）

- **感知：** 补全列表顶部出现带星的推荐。不聊天。不替换 IntelliSense。
- **延迟：** 必须像语言服务一样「已经在那儿」。星标来自本地模型 / 特征，不是一次 HTTP。
- **数据：** 高质量 GitHub 上的共现；后来有团队补全（仓库内统计）。
- **层：** G4 产品形态 + 一点 C2/E3 味的小模型。不卖 token，不卖 agent。
- **该抄：** 重排，不替换。星标是可教学的 UX：哪几条是「模型看好的」。
- **不抄（v0）：** 训练自己的补全模型。用规则 + 频率表先证明评测门。

## GitHub Copilot

- **感知：** 灰字整行 / 多行插入；侧栏能聊。
- **延迟：** 可接受 200ms–1s 的流式。人在等「生成」，不是在等「列表弹出」。
- **数据：** 大模型预训练 + 当前文件 / 邻文件提示。走 E2/E5。
- **层：** G4 + 买推理。问题已经从排序变成生成。
- **对我们：** 这是 v1.1 整行补全的邻居，不是 MVP。Batch/Flex 不能用在光标主循环。

## Tabnine / Continue

- **感知：** 补全或聊天；可本地、可自托管。
- **延迟：** 本地小模型可以很快；远端则回到 Copilot 量级。
- **数据：** 用户选模型；Continue 把 IDE 接到已有 API。
- **层：** G4 + 可选 E1 自托管。卖的是「模型你自己带」。
- **对我们：** 学他们的「推理可插」；v0 仍不插。先把特征列做对。

## Cursor Tab

- **感知：** 多行、跨编辑位置的预测，像「下一步你要改这儿」。
- **延迟：** 比星标列表松，比 agent 紧。
- **数据：** 当前编辑轨迹 + 仓库索引（G2）。
- **层：** G4 + 很深的 G2，后面还挂着 G1 agent。
- **对我们：** 不要假装第一周能做这个。relatedness 和 repo index 是故意推迟的层。

## 一张表

| 产品 | 用户以为它在做 | 实际决策 | 延迟量级 | 我们 MVP 学什么 |
| --- | --- | --- | --- | --- |
| IntelliCode | 更懂我的补全 | 重排 + 星标 | <50ms | 问题定义、UX、评测 |
| Copilot | 帮我写 | 生成 token | 百毫秒–秒 | 以后才买 E5 |
| Tabnine / Continue | 私有 / 自带模型 | 本地或自托管推理 | 看模型 | 可插拔，不是现在 |
| Cursor Tab | 预测下一笔编辑 | 编辑轨迹 + 仓库上下文 | 中 | 推迟 G2 整仓 |

## 差异化（现在唯一站得住的）

我们公开写：v0 **没有神经网络**。星标来自 import、同文件共现、接收者频率表。若 fixtures 上已经赢过字母序，再讨论是否买一次 completion API。
