# 用户与 JTBD

## 第一用户

正在写 TypeScript 的个人开发者。一个人、一个仓库、VS Code 或 Cursor。买方 = 使用者。没有采购、没有 SSO、没有「团队模型合规」。

## Job to be done

当我在表达式中间敲 `.` 或前缀时，**在 100ms 内把最可能的符号顶到最上面**，让我不用读完整张列表。

时间预算写进 job，不是写进「以后优化」。超过预算，补全已经结束，人开始手打——产品等于没出现。

## 使用场景

1. `console.` / `JSON.` / `Math.` —— 全局对象，答案几乎是公共先验。
2. `items.` / `rows.` —— 像数组，要的是 `map` / `filter`，不是字母序第一个。
3. 本文件已经 `import { readFile }`，再写 `fs.` —— 本文件用过的 API 应压过没用过的。
4. 打了 `fil` —— 前缀收窄后，`filter` 应压过 `fill`（频率 + 前缀，不是只前缀）。

## 非用户（现在）

| 人 | 为什么不是第一用户 |
| --- | --- |
| 企业平台团队 | 要 F4 封装、审计、VPC。MVP 没有身份层。 |
| 只写 Python / Go 的人 | 语言服务候选形状不同；先把 TS 的重排做对。 |
| 想用 agent 修 issue 的人 | Job 是定位→补丁→测试，不是补全排序。 |

## 用户能原谅 / 不能原谅

能原谅：偶发漏星、同一符号列表里出现两次（星标置顶 + 原位）。

不能原谅：卡 300ms、把错的 API 星标成第一、把源码打到网上（v0 没有网）。

## 一句话给自己

我们卖的是「前三个更准」，不是「会写代码的助手」。
